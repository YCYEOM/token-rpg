# Token RPG

Claude Code에 쓴 토큰이 그대로 캐릭터가 되는 턴제 RPG입니다.

실제로 코딩한 만큼 강해집니다. 출력 토큰은 공격력, 캐시 재사용은 방어력,
thinking 토큰은 치명타율이 됩니다. 버그 벌레부터 루트 권한의 군주까지, 개발자의 적 75종이 던전 보스입니다.

```
$ token-rpg open
Lv.28 코드 술사 🧑‍💻  HP 775 ATK 90 DEF 40.0 CRIT 30.5%  배분 56pt  던전 15개
```

## 설치

```bash
pipx install token-rpg
token-rpg open              # 집계 후 브라우저로 열기 (Ctrl+C 로 종료)
```

의존성은 없습니다. 표준 라이브러리만 씁니다. Python 3.9+ 만 있으면 macOS·리눅스·윈도우에서
같은 명령으로 돕니다 (`uv tool install token-rpg`·`pip install token-rpg` 도 같습니다).

아직 안 나온 최신 커밋을 받고 싶으면 GitHub 주소를 그대로 씁니다.

```bash
pipx install git+https://github.com/YCYEOM/token-rpg
```

## 상주 앱

브라우저 탭을 띄워 두지 않고 늘 켜 두고 싶으면 OS 마다 상주 앱이 있습니다. 둘은 같은 일을
합니다 — 저장 서버를 띄우고, 5분마다 사용량을 다시 집계하고, 아이콘을 누르면 게임을 엽니다.
저장 파일 하나를 브라우저와 함께 쓰므로 어느 쪽으로 해도 진행은 이어집니다.

### 윈도우 — 알림 영역(트레이)

```powershell
token-rpg-tray                  # 알림 영역에 상주 (콘솔 창 없음)
token-rpg-tray --startup on     # 로그인할 때 자동 실행
```

왼쪽 클릭이면 게임 창이 열립니다(Edge 앱 모드 — 주소창 없이 팝오버에 가깝습니다. 없으면 기본
브라우저). 오른쪽 클릭이면 `열기 · 지금 갱신 · 자동 실행 · 종료` 메뉴가 나옵니다.

윈도우 트레이는 맥 메뉴 막대와 달리 아이콘 옆에 글자를 못 답니다. 그래서 레벨과
배지가 툴팁 첫 줄(`Lv.31 49% ⬆`)로 갑니다 — 아이콘에 마우스를 올리면 보입니다.

게임 데이터는 `%LOCALAPPDATA%\token-rpg` 에 둡니다(`token-rpg where` 로 확인).
Stop 훅은 `cmd.exe` 문법으로 등록합니다.

### macOS — 메뉴 막대

`Token RPG.app`은 메뉴 막대에 게임패드 아이콘으로 상주합니다. 아이콘 옆에 레벨과
진행률(`Lv.31 49%`)이 뜨고, 마우스를 올리면 오늘 쓴 토큰·다음 레벨까지 남은 EXP를
보여줍니다. 아이콘을 누르면 팝오버 안에서 게임 전체를 그대로 할 수 있습니다.

배지: `⬆` 레벨이 올랐는데 아직 안 열어 봄 · `⛏` 원정이 가득 참 (수령해야 다시 쌓입니다).
앱은 5분마다 사용량을 다시 집계하므로 Codex·Gemini 사용분도 반영합니다.

받는 곳은 [릴리스 페이지](https://github.com/YCYEOM/token-rpg/releases/latest) —
`Token-RPG-macOS.dmg` 를 받아 안에 든 `Token RPG.app` 을 `Applications` 로 드래그합니다.
새 버전이 나오면 게임 화면의 **업데이트** 버튼이 DMG 를 직접 받아 앱을 갈아끼웁니다
([업데이트](#업데이트) 참고).

직접 빌드하려면 macOS Command Line Tools에서 다음을 실행합니다.

```bash
zsh scripts/build-macos-app.sh
open dist-macos/Token-RPG-macOS.dmg
```

앱은 독립적인 Swift/AppKit UI입니다. 다만 사용량 집계 로직은 번들에 든 `token_rpg.py`로
실행하므로 `python3`가 PATH에 있어야 합니다. 앱이 읽는 것은 로컬 로그뿐이고, 데이터를
외부로 보내지 않습니다.

지금 만드는 DMG는 **서명·공증하지 않은 개발 빌드**입니다. 다른 사람에게 배포하려면
Apple Developer ID로 서명하고 공증해야 Gatekeeper 경고 없이 열 수 있습니다.

## 자동 갱신

```bash
token-rpg install-hook      # Claude Code Stop 훅에 등록
```

이후 Claude Code가 응답을 마칠 때마다 스탯을 자동으로 갱신합니다(백그라운드, 1초 미만).
`token-rpg uninstall-hook`으로 되돌립니다. `~/.claude/settings.json`을 고치기 전에
항상 `.bak` 백업을 남깁니다.

## 게임 구조

**스탯** — 토큰 종류가 캐릭터 빌드를 정합니다. 사용 패턴이 곧 개성입니다.

| 스탯 | 출처 |
|---|---|
| HP | 출력 토큰 (기본 100) |
| ATK | 출력 토큰 |
| DEF | 캐시 읽기. 받는 피해를 **비율로** 깎는다 (보스 ATK 와 같으면 절반) |
| CRIT | thinking 토큰 (토큰만으로 최대 50%, 전체 상한 100%). 배분은 100% 가 되는 데까지만 들어갑니다 — 유물로 치명타가 오르면 남는 점수를 돌려줍니다. 토큰·유물만으로 넘친 만큼은 CDMG로 |
| CDMG | 치명타 피해. 기본 200%, 배분 +1%p/pt, 특성 '파괴의 유산' ×1.135/lv |
| SPD | API 호출 수 (+ 배분 포인트). 보스 SPD 의 배수마다 한 대씩 더 친다 (2.5배면 2타 + 50% 로 3타) |
| EXP | 입력 + 캐시 생성 + 출력 |

**던전** — 보스 15종이 한 층입니다. 누구 PC에서든 같은 던전이고, 층을 오를수록 보스가
지수로 강해집니다.

**층마다 테마가 다릅니다 (v0.15.0).** 예전에는 2층부터 같은 15종이 능력치만 커져서 다시
나왔습니다. 5층이면 같은 보스를 다섯 번째 보는 셈이었습니다.

| 층 | 테마 | 첫 보스 → 마지막 보스 |
|---|---|---|
| 1 | 코드 버그 | 버그 벌레 → 토큰 한도의 군주 |
| 2 | 인프라 장애 | 타임아웃 거미 → 온콜의 군주 |
| 3 | AI | 오타 프롬프트 임프 → 정렬 실패의 군주 |
| 4 | 회사 | 급한 건 모기 → 분기 실적의 군주 |
| 5 | 보안 | 피싱 낚시꾼 → 루트 권한의 군주 |

6층부터는 처음으로 돌아가 이름 앞에 "변종"이 붙습니다(변종 버그 벌레). 바뀌는 것은 이름과
이모지뿐입니다. 능력치·혼·유물 능력치는 칸 번호를 따르므로 밸런스와 저장은 그대로입니다. 내 스탯은
토큰에 선형으로 크고 보스는 거듭제곱근으로 큽니다. 그래서 막힌 곳은 토큰을 더 쓰면 반드시 넘습니다.

**극초반은 완만합니다 (v0.11.0)** — 예전엔 1스테이지 보스를 잡는 데 누적 200만 토큰이
필요했습니다. 갓 깐 Lv.1 은 ATK 가 0 인데 보스 DEF 가 8 이라 데미지가 한 점도 안 들어갔습니다.
시작조차 못 하고 꺾이는 구간이었습니다. 이제 6스테이지까지 보스 능력치를 눌러 두고 거기서
원래 곡선에 합류합니다 — **토큰 0 으로도 1스테이지는 깹니다.**

**레벨 구간이 모두 같습니다 (v0.20.3)** — 레벨 한 칸에 EXP 60만입니다. Lv.99 까지 5,880만, 이것이
초월 비용입니다. 하루 200만 토큰씩 한 달을 꽉 채우면 1초월합니다. 예전에는 뒤로 갈수록 한 칸이
비싸져(Lv.38 에서 360만, Lv.98 에서 1,000만) Lv.99 가 4.8억이었습니다. 하루 166만을 써도 8개월이 걸렸습니다.
대신 극초반은 조금 느려졌습니다 — 190만 토큰이면 예전엔 Lv.9, 이제 Lv.4 입니다(1,000만 토큰 언저리에서 같아집니다).
초월로 쌓이는 배분 포인트가 늘어 후반 층 진입이 빨라지지만, 특성이 곱으로 쌓이는 구조라 8번 초월한 캐릭터도
15~20% 안쪽입니다.

**초월** — Lv.99 에서 레벨을 1로 되돌리고 다시 올립니다. 레벨은 배분 포인트(2pt/레벨)를
주는데 99에서 막혀, 그 위로는 토큰을 아무리 써도 포인트가 안 늘었습니다. **이미 받은
포인트는 적립해 두고** 레벨과 칭호만 처음으로 돌립니다 — 초월 1회에 198pt 가 굳습니다.
스탯 배분·혼·유물·클리어 기록은 건드리지 않습니다. EXP 는 쓴 토큰이라 줄지 않습니다.
그래서 저장에 적힌 초월 횟수만큼 덜어내고 레벨을 다시 셉니다 (`hero()` 와 JS `lvNow()`
양쪽에 같은 식이 있고, `selftest` 가 표로 붙들어 둡니다).

**환생** — 클리어 기록을 버리고 혼을 얻습니다. 스탯 배분은 그대로 남습니다. 혼으로 사는 영구 특성은
배율(×1.135/레벨)이라, 배분 포인트로는 따라갈 수 없는 층 벽을 넘게 해줍니다.
영구 특성은 일곱입니다 — 힘의 유산(ATK ×1.135/레벨), 파괴의 유산(CDMG ×1.135/레벨),
혼의 유산(HP ×1.18/레벨), 신속의 유산(SPD +5%/레벨), **벽의 유산(DEF ×1.245/레벨)**,
수확(얻는 혼 +3%), 각성(배분 포인트 +4). 배율이 제각각인 이유는 아래에 적었습니다.

**파괴의 유산은 원래 +5%p 가산이었습니다.** 보스가 스테이지마다 ×1.28 로 곱해지는 곡선이라
가산은 따라가지 못했고, 혼 23,455 를 부어도 도달 스테이지가 9 에서 9 로 그대로였습니다
(같은 혼이면 힘의 유산이 16). 배율로 바꾸니 힘의 유산보다 한 칸 뒤에 서고, CRIT 이
높을수록 좁혀집니다 — 들러리가 아니라 빌드가 고르는 선택이 됐습니다. `selftest` 가
'사면 더 깊이 가고, 힘의 유산과 세 칸 안에 서되 넘지는 않는다'를 붙들고 있습니다.

**상한이 있는 능력치는 영구 특성으로 두지 않습니다** — 되팔 수 없는데 어느 레벨부터
값이 반으로 죽으면 그건 선택이 아니라 함정입니다. 그래서 CRIT(상한 100%)은 토큰·배분
포인트·유물로만 오릅니다. 일곱 다 상한이 없어서 언제 사도 죽지 않고, 선택은 실수를
피하는 문제가 아니라 **무엇을 먼저 사느냐**의 문제가 됩니다.

**DEF 는 받는 피해를 비율로 깎습니다.** `피해 = ATK² ÷ (ATK + DEF)` 입니다. DEF 가 상대
ATK 와 같은 자리수면 절반이고, 아무리 높아도 0 이 되지는 않습니다.

예전에는 그냥 빼기였습니다(`ATK − DEF`). 49스테이지 보스 ATK 가 336만인데 배분을 전부
DEF 에 넣어도 6만이라 피해가 **1.88%** 줄었습니다. 벽의 유산은 0레벨이든 70레벨이든
도달 스테이지가 똑같았습니다. 뚫고 못 뚫고의 벼랑도 있었습니다 — 상대 DEF 를 못 넘으면
타격당 1 피해였습니다. 비율로 바꾸니 둘 다 사라집니다. 지금은 벽 54레벨이면 같은 자리에서
피해가 96.2% 줄고 도달이 53 에서 55 로 갑니다.

**보스 SPD 의 배수마다 한 대씩 더 칩니다 (v0.20.9).** 2배면 2타, 3배면 3타이고 배수 사이는 확률입니다
(2.5배면 2타 + 50% 로 3타). 느리면 선공을 내줍니다(던전 목록에 빨갛게 뜹니다). 스탯 배분의 속도 줄이
다음 보스 기준 지금 몇 타인지와 한 대 더 치는 데까지 남은 점수를 보여 줍니다.

v0.19.2 부터 v0.20.8 까지는 2타가 천장이었습니다. 상한을 없애도 속도가 정답이 되지 않습니다 — 속도에 점수를
옮기면 공격이 줄고, 공격이 보스 DEF 보다 낮을 때 한 대 피해는 공격의 제곱으로 줄어듭니다. 개발자 저장으로 재 보니
배분의 10~90% 를 속도에 넣어도 벽이 212~216 으로 거의 같았습니다. 속도형도 공격형도 됩니다.
상한을 없애면 진행이 11% 빨라져 보스 HP 성장을 ×1.331 → ×1.337 로 올렸습니다(TypeSafe 판정: 진행 중앙 -2%,
특성 균형·빌드 다양성은 지금 수준 이상).

**보스 SPD 는 스테이지마다 3씩 오릅니다.** 다른 능력치처럼 ×1.28 씩 오르던 v0.19.1 까지는
배분으로 따라잡을 수 없어서, 깊은 층에서는 아무도 속도에 점수를 넣지 않았습니다. 지금은
배분 1점(SPD +3)이 보스 한 스테이지분입니다.
테스트 캐릭터 여섯으로 재면 초반·후반 모두 배분의 10~60% 가 속도로 가고,
층 진입 회차는 지금과 3회 안에서 움직입니다(TypeSafe 확인).

**220~230레벨 생존 조정 (v0.20.10)** — 혼의 유산을 ×1.18/레벨로 올리고 보스 HP 성장을 ×1.355 로 조정했습니다.
혼·벽 특성 각 230레벨과 배분 350pt 기준으로 다음 보스의 한 대를 버팁니다. 보스 HP 상승으로 공격 위주 진행 속도를
보정했습니다. 특성 배율과 진행 속도는 selftest 기준으로 확인합니다.

**특성 배율은 그 스탯이 무엇과 겨루는지에 맞춥니다.** 전부 ×1.12 이던 시절에는 벽과
신속이 죽어 있었습니다. 혼을 얼마를 부어도 도달 스테이지가 그대로라, 사면 손해인
특성이었습니다.

| 유산 | 배율 | 왜 |
|---|---|---|
| 힘 · 파괴 | ×1.135 | 피해에 곱으로 붙습니다. v0.19.8 에서 벽과 같은 칸을 밀도록 1.12 에서 올렸습니다 |
| 혼(HP) | ×1.18 | 피해를 견디는 쪽. v0.20.10 에서 220~230레벨의 한 대 생존 목표에 맞췄습니다 |
| 신속(SPD) | +5%(덧셈) | 곱하면 속도가 금방 공짜가 됩니다. 싸게 배분 점수를 아껴 줍니다 |
| 벽(DEF) | ×1.245 | 6스테이지부터 보스 ATK 는 ×1.245 씩 오릅니다. v0.19.8 에서 1.28 → 1.25, v0.20.4 에서 1.245 로 내려 힘과 같은 칸을 밉니다 |

| 특성 레벨 | 0 | 10 | 20 | 30 | 40 | 60 |
|---|---|---|---|---|---|---|
| 힘의 유산 도달 | 10 | 12 | 14 | 16 | 19 | 23 |
| 혼의 유산 도달 | 10 | 12 | 14 | 16 | 19 | 23 |
| 벽의 유산 도달 | 10 | 11 | 13 | 16 | 18 | 22 |
| 파괴의 유산 도달 | 10 | 11 | 13 | 15 | 18 | 22 |

넷이 전 구간에서 한 칸 안에 서고 한 번도 힘의 유산을 넘지 않습니다. `selftest` 가
넷 전부에 대해 "사면 더 깊이 가고, 힘과 네 칸 안에 서되 넘지 않는다"를 붙들고 있습니다.

**격파하면 가장 약한 유물 하나를 강화합니다 (v0.20.5).** 먼저 그 유물을 얻을 수 있는 가장 깊은 층으로

능력치마다 기본 수치가 달라 % 를 그대로 견줄 수 없기 때문입니다. 레이드 카드에 강화할 유물이 미리 보입니다 —
지금 상태와 강화 후, 층을 옮기는지 등급을 올리는지, 왜 그 유물인지(최고치 대비 몇 %, 다음으로 약한 유물)를 적습니다.

얕은 층 신화가 나중에 깊은 층 영웅에게 밀려 사라졌습니다. 이제 얕은 층 신화는 지금 층으로 옮겨 줘서 밀리지 않습니다.

180스테이지까지 한 칸도 건너뛰지 않고 봅니다. 연속 사용 배율은 레이드에 붙지 않습니다 — 레이드가 이미
한 주의 사용량을 재기 때문입니다. 환생 사이 보조 수입의 최대치는 21.6판치에서 22.2판치가 됩니다(+2.6%).

**슬롯** — 3x3 릴, 가로 셋·세로 셋·대각선 둘까지 여덟 줄. 칸은 왼쪽부터 차례로 서고,

누구나 세로도 셉니다 — 화면이 말하는 것과 규칙이 어긋나면 그건 규칙이 틀린 겁니다.

운으로 버는 칸입니다. 잘 하고 못 하고가 없으니 하루 판수(`SLOT_TRIES`, 10판)만 주고, 지급을

버느냐가 아니라 언제 받느냐만 바꿉니다. 열 판 모두 꽝인 날은 2.2% 입니다.

**혼 사냥은 v0.18.5 에 없앴습니다.** 과녁에서 표식을 멈추는 칸이었습니다. 그 몫(하루 2 격파분,
다 맞히면 1.5배 = 3 격파분)을 슬롯으로 옮겨 슬롯 예산이 1 에서 4 가 됐습니다. 보조 수입 총량은
혼 사냥을 다 맞히던 때와 같습니다 — 밸런스 검사 결과도 그대로입니다. 혼 사냥을 덜 맞히던 사람은
그만큼 더 받습니다.
스테이지를 하나 깨면 열리고, 돌리는 순간 한 판이 빠지며 자정에 초기화합니다.

돌리는 재미까지 하루 예산에 묶을 이유는 없습니다.

평균 배당으로 붙들고, 슬롯 수입을 미션과 묶어 환생 수입과 견줍니다. 이 상한 때문에
`SLOT_BUDGET` 은 4 가 한계입니다 — 더 올리면 1층에서 주간 보조 수입이 환생의 2배를 넘습니다.

올려도 변이가 없을 때보다 쉬워지지 않는다"를 붙들고 있습니다.

다섯 변이의 세기는 "최적 배분의 여유가 1/3 로 준다"에 맞췄습니다. 실명과 무감각은 빌드를 탑니다 — 치명타에
기대지 않는 빌드는 가볍게 지나갑니다.

**보스 도감과 황금 개체 (v0.16.0)** — 보스를 처음 이기면 도감 윗줄에 찍힙니다. 싸울 때마다 0.1%
확률로 그 보스의 **황금 개체**가 대신 나옵니다. 이름 앞에 "황금"이 붙고 능력치는 같습니다.
이기면 도감 아랫줄에 찍힙니다. 자동 반복과 수동 도전 모두 해당합니다.

| | 값 |
|---|---|
| 출현 확률 | 0.1% — 자동 반복(1초에 한 판)을 켜 두면 17분에 한 번꼴 |
| 처음 잡을 때 | 그 스테이지 혼 한 판치 (보조 수입용 값) |
| 황금 한 칸 | 얻는 혼 +0.5% (영구) |
| 한 층의 황금 15종 | 배분 포인트 +4 (영구) |
| 전부(75종) | 얻는 혼 +37.5%, 배분 +20pt |

**이미 잡은 황금은 다시 잡아도 혼을 주지 않습니다.** 자동 반복이 1초에 한 판이라, 주면 켜 두기만
해도 혼이 쌓여 환생 기운 제한을 돕니다. 유물 중복을 1/20 로 묶어 둔 것과 같은 이유입니다.

가며 잡으면 켜 둔 채 네 시간쯤, 15칸을 한꺼번에 돌리면 열네 시간쯤 듭니다.
6층부터 나오는 변종은 같은 칸을 씁니다 — 도감은 75종이 끝입니다. 6층은 1층 줄, 7층은 2층 줄에 찍히고,
도감 카드가 지금 층이 어느 줄인지 표시합니다.

**처음 잡을 때 보상이 한 판치인 이유.** 5배로 넣고 재 보니 처음 한 번만 줘도 5층·6층이 환생
2~3회에 열렸습니다(기준은 층당 4~12회). 한 층에 황금이 15칸이라, 환생 한 번 사이에 환생 다섯 번치
혼이 들어왔습니다. 한 판치면 5~9층이 층당 4~7회로 기준 안입니다. `selftest` 가 하루 종일 켜 두고
값이 큰 칸부터 잡는 경우로 이 기준을 붙들고 있습니다.
도감이 없던 저장은 이미 깬 스테이지의 보스를 본 것으로 찍어 줍니다.

**환생 보너스** — 환생할 때마다 얻는 혼(환생·원정·미션·유물 중복)이 영구히 +2%씩 늡니다.
10회면 +20%, 25회면 +50%. 혼 배수는 환생·유물·수확·도감 넷이 곱해지므로, 캐릭터 카드 아래
`얻는 혼 x1.34 (환생 +2% · 유물 +6% · 수확 +24%)` 줄에 합쳐서 보여 줍니다.

**시작점** — 설치한 날부터 셉니다. 이미 몇 달 치 로그가 쌓여 있으면 깔자마자 고레벨로
시작해 성장이 통째로 사라지기 때문입니다. 처음 실행할 때 기준을 정하고 `config.json` 에
남깁니다. 이미 쓰던 설치(스냅샷이나 저장이 남아 있는 설치)는 과거를 그대로 지킵니다.

```bash
token-rpg since              # 지금 기준 보기
token-rpg since all          # 예전 기록까지 전부 세기
token-rpg since 2026-01-01   # 특정 날짜부터
```

세션 파일 단위로 거르므로 기준일을 걸친 세션 하나는 통째로 셉니다.

**누적은 지워지지 않습니다** — Claude Code 는 30일 지난 대화 로그를 스스로 지웁니다
(`cleanupPeriodDays`). 그래서 v0.14.6 부터 세션 파일별 합계를 `ledger.json` 장부에 적어 두고,
로그가 사라져도 장부 값으로 계속 셉니다. 장부가 생기기 전에 이미 지워진 로그는 되살릴 수 없습니다.

## 업데이트

새 버전이 있으면 게임 화면 맨 위에 알림이 뜹니다. **업데이트** 버튼을 누르면 깔린 방식
(`uv tool`·`pipx`)을 알아서 찾아 올립니다. 끝나면 창을 다시 열면 됩니다.

```bash
token-rpg update        # 터미널에서도 같은 일을 합니다
```

메뉴 막대 앱도 같은 버튼입니다. 누르면 릴리스의 DMG 를 직접 받아 앱을 갈아끼우고, 앱이
잠깐 닫혔다 다시 뜹니다. 실패하면 이유를 적어 두고 다음에 열 때 알림 아래에 보여 줍니다
(과정은 데이터 폴더의 `update.log`). 앱을 `Applications` 로 옮기지 않고 열었으면 옮기라고 알립니다.
v0.18.2 까지는 브라우저로 DMG 를 받아 설치한 Mac 에서 이 버튼이 앱을 닫기만 하고 다시 띄우지 못했습니다 —
macOS 가 받은 앱에 붙이는 '인터넷에서 받음' 딱지가 새 앱에도 옮겨 붙어 실행이 막혔습니다. 지금은 갈아끼우기
전에 딱지를 지웁니다. 새 버전 확인과 내려받기도 조회 제한(한 IP 에서 시간당 60번)이 없는 주소로 바꿨습니다.
터미널의 `token-rpg update` 는
앱 사본을 건드리지 않고 받을 주소만 알려 줍니다.

버전 확인은 GitHub 릴리스 API 한 번이고, **파이썬 쪽에서 하고 결과를 60초 재사용합니다**
(게임 페이지가 직접 바깥으로 나가지 않습니다). 보내는 것은 버전 문자열뿐이고 사용량·로그는
어디로도 나가지 않습니다. 끄려면 `config.json` 에 `"updateCheck": false` 를 넣습니다.

## 여러 PC 합산

각 PC에서 `token-rpg export`를 돌리면 4KB짜리 스냅샷만 남습니다. 스냅샷 폴더를 클라우드
동기화 폴더로 지정하면 모든 기기가 합쳐집니다. 양쪽 OS 에서 같은 폴더를 가리키면 됩니다.

```bash
# macOS · 리눅스 (~/.zshrc 나 ~/.bashrc 에)
export TOKEN_RPG_SNAPSHOTS=~/Dropbox/token-rpg
```
```powershell
# 윈도우 — setx 는 새로 여는 창부터 적용됩니다
setx TOKEN_RPG_SNAPSHOTS "$env:USERPROFILE\Dropbox\token-rpg"
```

지정한 뒤 각 PC 에서 `token-rpg export` 를 한 번 돌리면 그 폴더에 스냅샷이 생깁니다.
기존 `snapshots` 폴더에 있던 파일은 새 폴더로 옮깁니다 (`token-rpg where` 로 위치 확인).

**사용량은 알아서 합칩니다.** PC 마다 `<호스트이름>.json` 을 따로 쓰고 합산할 때 전부
더하므로, 파일당 PC 하나라 충돌이 구조적으로 없습니다. 여러 PC 에서 동시에 코딩해도 됩니다.

**게임 진행은 한 번에 한 PC 에서만 합니다.** `game.save` 는 파일 하나를 기기끼리 같이 씁니다.
한 PC 안에서는 브라우저 탭과 상주 앱이 `rev` 번호로 서로를 막아 줍니다(오래된 창이
덮어쓰려 하면 거부하고 최신 저장을 불러옵니다). 다른 PC 끼리는 서로의 `rev` 를 볼 수 없습니다.
두 기기에서 동시에 켜 두면 동기화 서비스가 충돌 사본을 만들거나 늦게 쓴 쪽이 덮어씁니다.
한쪽에서 게임 창과 상주 앱을 닫고 동기화가 끝난 뒤 다른 쪽을 열면 됩니다.

**진행 저장은 봉인해서 적습니다.** `game.save` 는 v0.10.0 부터 `base64(JSON).서명` 한 줄이라
텍스트 편집기로 열어 혼·환생·배분을 고칠 수 없습니다. 서명이 맞지 않으면 불러오지 않습니다.
쓰던 설치는 처음 갱신할 때 자동으로 봉인하니 따로 할 일은 없습니다 — **다만 이 파일을 같이 쓰는
설치본은 전부 v0.10.0 이상이어야 합니다.** 한 PC 안에서도 설치본이 여러 개일 수 있으니
(`uv tool`·`pip`·맥 앱 번들) `token-rpg update` 를 각각 돌려야 합니다.

스냅샷(`snapshots/*.json`)도 봉인해서 쓰지만 **평문도 받아 줍니다.** 옛 설치본의 훅이 평문으로
덮어쓰는 일이 흔한데 거기서 거부하면 그 PC 토큰이 0 이 되기 때문입니다. 스냅샷은 매번 진짜
로그에서 다시 만들므로 손대도 다음 갱신에 덮어씁니다.

열쇠가 소스 안에 있어 작정하면 위조할 수 있습니다. 막는 대상은 "파일 열어서 0 하나 더 붙이기"입니다.

## 데이터

`~/.claude/projects/**/*.jsonl`의 `usage` 필드만 읽습니다. Codex·Gemini CLI 를 쓰면
[프로바이더](#프로바이더) 표의 위치도 같은 방식으로 읽습니다. **읽기 전용이고,
아무것도 밖으로 보내지 않습니다.** 게임 데이터는
`~/.local/share/token-rpg/`(또는 `$XDG_DATA_HOME`)에 저장합니다. 진행 상황은 스냅샷 폴더의
`game.save` 파일 하나에 두고, 브라우저와 상주 앱이 같이 씁니다. 서버 없이 `game.html` 을
파일로 직접 열었을 때만 그 브라우저의 localStorage 에 둡니다.

## 검증

```bash
python token_rpg.py selftest
```

파이썬 쪽 집계·병합·밸런스를 보고, 이어서 게임 화면을 실제로 돌립니다.

밸런스는 고정 영웅 여섯(`BALANCE_HEROES` — 첫 주·보통·많이 씀·초월 직전·출력만·캐시만)으로
늘 봅니다. 이 PC 에 사용 기록이 있으면 그 영웅으로도 한 번 더 봅니다. 예전에는 이 PC 의
영웅 하나로만 봤고, 기록이 없는 CI 에서는 밸런스 검증과 그 뒤의 검사가 통째로 빠졌습니다.

화면과 전투는
`token_rpg.py` 안의 JS 인데, 파이썬과 같은 식이 두 벌이라 한쪽만 고치면 어긋납니다.
`tests/game_smoke.js` 가 가짜 DOM 위에 그 스크립트를 올리고 한 바퀴 돕니다 — 배분, 전투,
슬롯, 미션, 원정, 환생, 자동 도전, 특성 구입, 저장 코드, 초월, 옛 저장 이관까지.

| 보는 것 | 잡는 것 |
|---|---|
| 예외가 안 난다 | 선언 순서, 없는 id, 오타 (v0.14.4 는 화면이 통째로 비었습니다) |
| 그린 글자에 NaN·undefined 가 없다 | 없는 상수를 읽는 계산 (v0.14.5 의 NaN 레벨) |
| 파이썬과 값이 같다 | 보스·레벨·특성 비용·최종 스탯·벽 스테이지 |

`node` 가 있어야 돕니다. 없으면 알리고 건너뛰며, CI 에서는 실패합니다. 깔린 사본에는
`tests/` 가 없어 이 단계가 없습니다. 브라우저가 아니라서 배치와 CSS 는 보지 못합니다.

## 프로바이더

여러 AI 툴의 사용량을 한 캐릭터로 합산합니다.

```bash
token-rpg providers                          # 목록과 스캔 위치
token-rpg scan add codex '~/backup/*/sessions'   # 로그가 기본 위치 밖일 때
token-rpg disable codex                      # 특정 프로바이더 끄기
```

| 프로바이더 | 기본 위치 | 상태 |
|---|---|---|
| `claude-code` | `~/.claude/projects` | 검증됨 |
| `codex` | `~/.codex/sessions` | 검증됨 (codex cli 0.153.4) |
| `gemini` | `~/.gemini/tmp` | 검증됨 (gemini cli 0.59.0) |

Codex CLI는 `cached_input_tokens`·`reasoning_output_tokens`를 남겨 DEF·CRIT까지
그대로 대응합니다. `token_count` 이벤트의 `total_token_usage`는 세션 누적이라
파일마다 마지막 값만 셉니다.

Gemini CLI는 텔레메트리 없이도 세션 로그(`chats/session-*.jsonl`)의 답변마다
`tokens`(input·output·cached·thoughts)를 남깁니다. 답변 단위라 전부 더하고,
`cached`는 DEF, `thoughts`는 CRIT로 대응합니다.

**웹에서 쓴 것은 잡히지 않습니다.** ChatGPT·Gemini 웹, Cursor, GitHub Copilot은
토큰 집계를 서버에서만 하고 로컬에 숫자를 남기지 않습니다. CLI 툴을 설치해서
써야 기록이 생깁니다.

새 툴을 붙이려면 `PROVIDERS`에 "파일 하나를 읽어 토큰 합계를 돌려주는 함수"
하나만 추가하면 됩니다. 또는 스냅샷 JSON을 직접 뱉어도 됩니다:

```json
{"host": "내PC", "updated": "2026-09-10T00:00:00+00:00",
 "agg": {"input": 0, "output": 0, "cache_read": 0, "thinking": 0, "calls": 0},
 "projects": {"프로젝트명": 0}, "days": ["2026-09-10"]}
```
